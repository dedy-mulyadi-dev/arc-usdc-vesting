# Arc Microgrants Submission — USDC Vesting

## Project Name
USDC Vesting — Linear Vesting & Scheduled Payouts on Arc

## One-line description
A trustless USDC vesting app on Arc where senders lock funds for a beneficiary and vesting happens linearly over time — no admin, no custodian, just a smart contract.

---

## What it does

USDC Vesting lets anyone create a linear vesting schedule on Arc Mainnet:

- **Sender** deposits USDC into the contract, specifying a beneficiary address, a start time, and a duration.
- **Beneficiary** can claim their vested USDC at any time as it accrues linearly from start to end.
- **Sender** can cancel at any time and reclaim only the unvested portion — the beneficiary keeps everything already vested.
- After a cancellation, the beneficiary can still claim their vested remainder via `claimAfterCancel`.
- No owner, no admin, no upgrade proxy. No one can move a user's funds except the rightful recipient.

Use cases: employee token grants, contractor payouts, DAO contributor rewards, founder vesting, escrow-style delayed payments.

---

## How Arc Studio was used

This project was built entirely inside Arc Studio from a blank canvas:

1. **Smart contract** — Arc Studio wrote `VestingVault.sol` in Solidity 0.8.28 with OpenZeppelin SafeERC20 and ReentrancyGuard. It uses the USDC ERC-20 interface on Arc and reads `decimals()` from the token contract rather than hardcoding.

2. **Security review (reported by Arc Studio, not independently verified)** — Arc Studio reported running its own automated security review and fixing three issues before deployment:
   - `claimAfterCancel` could bypass vesting and drain active schedules
   - Cancelled schedules could be overwritten, destroying the beneficiary's vested remainder
   - Fully claimed schedules were never deleted, permanently blocking future schedules for the same pair

   This is not a third-party audit. The contract is **UNAUDITED**.

3. **Tests** — `contracts/test` contains 55 Foundry test functions across 5 test files plus a shared base, including 5 fuzz tests. The count comes from the repository source; the author has not independently re-run the suite for this document.

4. **Static analysis** — Arc Studio reported running Slither with no actionable findings. This was not independently reproduced by the author.

5. **Deployment** — Arc Studio deployed to Arc Testnet. Mainnet deployment was done via Remix using the Standard JSON input and deployment pack generated by Arc Studio.

6. **Frontend** — Arc Studio built a React + Vite + wagmi v2 + ConnectKit UI with:
   - Create schedule form with confirmation panel, self-vesting warning, exact USDC approval
   - View & Claim panel with live polling, Active/Cancelled/No schedule states
   - Network switcher (Arc Testnet / Arc Mainnet) with `wallet_switchEthereumChain`
   - Mainnet banner: "Unaudited. Early access. Use small amounts only."
   - Cancel with `simulateContract` pre-flight to distinguish NothingToCancel vs network errors
